PORTAMESHRF + AUTO REPEATER: BUILDING THIS FORK

Upstream base: see UPSTREAM-COMMIT.txt and UPSTREAM-SYNC.md.
Use this fork's source, not a patch against the old November 9 nightly.
Compiler: GNU Arm Embedded GCC 9.2.1 20191025; Ninja.
Dependencies: CMake, Python3, PyYAML, pyelftools, Python lz4,
lz4 CLI, dfu-util/dfu-suffix, and a host C++17 compiler for tests.

  git clone --recurse-submodules --branch next https://github.com/Nhscan/mayhem-firmware-Repeater-PortaMeshRF-fork.git
  cd mayhem-firmware-Repeater-PortaMeshRF-fork
  python3 tests/check_message_ids.py
  python3 tests/auto_repeater/run_host_tests.py
  make -C tools/lora_bench
  python3 tools/update_external_tier_ld.py
  version="pmesh_$(git rev-parse --short=7 HEAD)"
  cmake -S . -B build -G Ninja -DCMAKE_POLICY_VERSION_MINIMUM=3.5 -DMAYHEM_CUSTOM_VERSION="$version"
  cmake --build build --target oci -j4
  python3 tests/auto_repeater/check_layout.py build
  python3 tests/auto_repeater/check_runtime_memory.py build
  python3 tests/auto_repeater/check_install.py build "$version"

Commands above use a Linux shell. The GitHub Actions workflow
.github/workflows/portameshrf-branding.yml builds and packages on Ubuntu.
It publishes test artifacts only to this fork; no PR or upstream push.

The custom version is cached. Use a clean build directory for another version.
The workflow creates a USTAR updater archive with APPS and BASEBAND before
FIRMWARE, then runs check_update_archive.py. Do not substitute an ordinary
TAR with extended headers; the device updater cannot read those headers.

Keep the matching SD_CARD/APPS and BASEBAND, updater TAR and exact 1 MiB
BIN together. Internal meshtastic.ppma/settings names are intentionally
retained for compatibility. See PORTAMESHRF.md for setup and keys.
Passing software checks does not replace physical H4M RF/UI/SD testing.
